# 프렙 카페 운영 관리 프로그램 TRD

- 기준: `docs/01_PRD.md`, `docs/02_FRD.md`, `design/`
- 상태: 검토 기준 확정본. 구현은 시작하지 않았다.
- 운영 범위: 운영자 1인 계정으로 사용하는 앱을 전제로 한다.

## 사용할 기술과 선택 이유

- **Next.js와 TypeScript**: 웹 화면과 서버 처리를 한 프로젝트에서 만들고 Vercel에 배포한다. TypeScript는 자료 형태 오류를 개발 중 찾도록 돕는다.
- **Supabase PostgreSQL**: 판매·비용·메뉴·레시피·가격·실사처럼 서로 연결된 자료를 저장한다. 관계 제약과 트랜잭션(여러 저장이 전부 성공하거나 전부 취소되는 처리)을 사용한다.
- **Supabase Auth**: 운영자 1인의 로그인과 세션 관리를 맡긴다. 직원 초대와 역할 관리는 MVP에 넣지 않는다.
- **서울 리전**: Supabase `ap-northeast-2`와 Vercel `icn1`을 추천한다. 사용자와 가까운 곳에 처리 환경과 데이터베이스를 두어 통신 지연을 줄인다. [Supabase 리전](https://supabase.com/docs/guides/platform/regions), [Vercel 리전](https://vercel.com/docs/regions)
- Vercel 함수의 파일 공간은 영구 자료 저장에 사용하지 않고 DB에 기록한다. Vercel 서버리스 실행 공간은 지속 파일 저장소로 보장되지 않는다. [Vercel 파일 시스템 안내](https://vercel.com/guides/why-does-my-serverless-function-work-locally-but-not-when-deployed)

## 처리 순서

1. 운영자가 로그인하고 가상 샘플 자료를 연다. 초기 적재에는 JSON만 한 번 사용하고, 같은 내용의 엑셀은 더하지 않는다.
2. 판매·비용을 입력·수정·삭제하고, 실제 재고 수량과 실사일을 입력한다. 입력값을 검사한 후 DB에 저장한다.
3. 영업달력의 모든 날짜가 완료된 월만 고른다. 일부 날짜가 미완료인 달은 확정 결과에서 제외한다.
4. 현재 저장된 최신 레시피와 재료 가격으로 과거 판매까지 다시 계산한다. 메뉴 공헌이익에서는 수수료를 빼지 않는다. 월 손익에는 결제 수수료와 날짜별 실제 비용을 반영하고 월별 비용 계획은 더하지 않는다.
5. 메뉴 수익성, 선택 월의 재산정 손익, 재료별 마지막 실사 수량·날짜를 표시한다. 실사 기록이 없으면 0 대신 “실사 기록 없음”을 표시한다.

계산은 십진수 자료형으로 수행해 부동소수점 오차를 줄인다. 중간 계산을 유지하고 최종 원화 표시에서 반올림하는 방식을 추천한다.

## 주요 파일이 맡는 일

- `app/`: 로그인, 판매·비용 입력, 재고 실사, 월별 결과 화면과 서버 요청
- `components/`: 시안의 입력창·표·버튼 등 화면 요소
- `lib/db/`: DB 조회와 저장
- `lib/calculations/`: 메뉴 원가, 월별 손익, 마감 월 판정
- `lib/validation/`: 입력 누락·단위·숫자·기간 검사
- `supabase/migrations/`: 자료 표, 관계, 필수 제약, 접근 제한 규칙
- `scripts/seed-sample`: JSON 샘플을 한 번만 DB에 넣는 준비 작업
- `.env.example`: 환경 변수 이름의 예시. 실제 비밀 키는 별도 환경 설정에 두고 GitHub에 올리지 않는다.

## 데이터 저장·이동·복구

- 판매·비용·레시피·가격·영업달력·실사 기록은 Supabase DB에 저장한다. 앱을 닫거나 다시 로그인해도 남는다.
- 초기 샘플은 `매장운영데이터.json`만 사용한다. 엑셀과 JSON을 함께 적재하지 않았는지 행 수와 식별값을 대조한다.
- 수업 후 엑셀 가져오기는 열 제목·날짜·숫자·기준 단위·참조 ID를 검사하고 미리보기와 오류 목록을 보여주는 방식을 추천한다. 같은 ID와 내용은 중복 적재하지 않고, ID는 같지만 내용이 다르면 자동 덮어쓰기 대신 충돌로 알린다.
- 수업 후 백업은 자료 형식 버전을 포함한 JSON 스냅샷으로 내려받는다. 복원은 파일 전체 검사와 미리보기 후 기존 자료 전체를 교체하는 방식을 추천한다. 복원 전에 백업하고, 오류가 나면 기존 자료가 바뀌지 않도록 전체를 취소한다.
- 앱 백업 기능과 서비스 자동 백업은 별개다. Supabase Free에는 자동 DB 백업이 없고, Pro는 일일 백업을 7일 보관한다. Supabase 파일 저장소를 쓰지 않는 구조여서 DB 기록만 백업 대상으로 삼는다. [Supabase 백업 안내](https://supabase.com/docs/guides/platform/backups)

## 정보 보호

- GitHub 저장소는 비공개로 두고, 실제 매장 자료·백업·환경 변수 파일을 올리지 않는다. 가상 샘플만 저장소에 둘 수 있다.
- 모든 자료 표에 **행 단위 접근 제한(RLS)**을 적용해 로그인한 운영자만 자료를 읽고 수정하게 한다. 비로그인 접근은 차단하고 전체 권한 키는 서버 환경 변수에서만 사용한다. [Supabase RLS 안내](https://supabase.com/docs/guides/database/postgres/row-level-security)
- HTTPS로 자료를 전송하고 고객 이름·카드번호·결제 자격정보를 수집하지 않는다. 오류 기록에 비밀번호, 키, 전체 매출 자료를 남기지 않는다.
- 내려받은 백업은 매장 재무 자료로 취급해 기기 내 보호된 위치에 보관한다. 자료 보유·폐기 기간은 PRD에서 정하지 않았으므로 실제 운영 전 별도로 정한다.

## 오류 대응

- 필수값 누락, 잘못된 숫자·날짜·단위, 음수 수량은 저장하지 않고 문제 항목을 안내한다. 빈칸을 0으로 바꾸지 않는다.
- 레시피·가격이 없거나 마감 상태를 판정할 수 없으면 0으로 계산하지 않고 계산 불가 사유를 표시한다.
- 저장 중 네트워크·DB 오류가 나면 성공으로 알리지 않고 입력 내용을 보존해 재시도할 수 있게 한다. 삭제는 대상을 확인한 뒤 처리한다.
- 수업 후 엑셀 가져오기와 복원은 파일 전체를 검사한다. 잘못된 행이나 파일을 정상 반영한 것처럼 알리지 않는다.

## 배포 방법

- 비공개 GitHub 저장소를 Vercel에 연결한다. 작업 브랜치는 미리보기 배포로 확인하고 `main` 반영은 운영 배포로 삼는다. [Vercel Git 배포](https://vercel.com/docs/git)
- 4시간 실습은 가상 자료만 쓰는 데모로 배포하는 것을 추천한다. Vercel Hobby는 개인·비상업 전용이며, Supabase Free는 DB 500MB·파일 저장 1GB이고 1주 비활성이면 정지하며 자동 DB 백업이 없다. [Vercel Hobby 조건](https://vercel.com/docs/plans/hobby), [Supabase 요금제](https://supabase.com/pricing)
- 실제 매장 상업 운영에는 유료 플랜을 추천한다. 검토일(2026-09-28) 공개 기본 가격은 Vercel Pro 월 US$20, Supabase Pro 월 US$25로 약 US$45/월이며 세금·초과 사용료는 별도일 수 있다. Supabase Pro에는 일일 DB 백업 7일 보관이 포함된다. 가격은 바뀔 수 있다. [Vercel 가격](https://vercel.com/pricing), [Supabase 가격](https://supabase.com/pricing)
- 샘플 최신 재료 가격은 2026-09-01 적용분이다. 이후 가격 갱신 방법은 PRD 미정 사항이다. 이 문서에서는 가격 편집 기능을 추가하지 않으며 실제 운영 전에 갱신 방법을 정해야 한다.

## 확인 방법

- 초기 적재 후 판매 6,112건, 비용 3,560건 및 메뉴·재료·레시피 개수를 자료 설명과 대조하고, 엑셀과 JSON이 중복 합산되지 않았는지 확인한다.
- FRD 예시를 대조한다. M01 10잔 × ₩4,000, 할인 ₩1,000이면 순매출 ₩39,000, 원가 ₩4,968, 수수료 전 공헌이익 ₩34,032다. 수수료 ₩600과 날짜별 비용 ₩5,000을 반영한 재산정 손익은 ₩28,432이며 월 비용 계획은 제외한다.
- 2026년 8월은 마감 월로 선택되고, 9월은 미완료 날짜가 있는 동안 결과에서 제외되는지 확인한다.
- 저장 후 다시 로그인해 값이 남는지, 수정·삭제가 결과에 반영되는지, 실사 수량 0과 “실사 기록 없음”이 구분되는지 확인한다.
- 잘못된 입력·누락된 가격·저장 통신 오류가 정상 결과로 둔갑하지 않는지, 비로그인 접근이 차단되는지 확인한다.
- 현재 샘플 규모에서 월 결과가 보통 2초 이내 조회되는 것을 권장 목표로 삼는다. 측정 결과는 구현 후 확인한다.
