# 프렙 카페 운영 관리 프로그램 FRD

- 기준 문서: docs/01_PRD.md
- 상태: 기능 요구사항 초안. PRD에서 확정한 범위와 사용자의 추가 선택을 반영했다. PRD나 자료가 정하지 않은 기준은 “제안” 또는 “추후 확인”으로 표시했다.
- MVP는 최소 기능을 뜻한다. 실습 중에는 판매·비용·실사 기록에서 월별 결과를 확인하는 흐름을 구현한다.

## 전체 사용 순서

1. 제공된 가상 매장 샘플 자료를 시작 자료로 연다. 엑셀과 JSON 중 같은 기록을 두 번 더하지 않는다.
2. 판매 기록을 입력하거나 기존 기록을 수정·삭제한다.
3. 날짜별 비용 기록을 입력하거나 기존 기록을 수정·삭제한다.
4. 재료별 실제 수량을 센 날짜·시각과 함께 기록한다.
5. 영업달력에서 해당 월의 모든 날짜가 기록 완료인 월을 선택한다.
6. 메뉴별 수익성과 현재 재료 가격 기준으로 재산정한 월 손익을 확인한다.
7. 재료별 마지막 실사 수량과 실사일을 확인한다. 실사 기록이 없는 재료는 0으로 보지 않는다.

## 자료와 시안에 관한 기준

### 자료에서 확인한 사실

- 판매 자료는 주문별 기록이 아니라 날짜·메뉴·판매채널별 수량 집계다. 6,112개 판매 ID와 이 조합에는 샘플 중복이 없다.
- 판매 기록에는 판매 당시 단가, 할인 총액, 순매출, 결제 수수료와 당시 메뉴 원가가 있다. 샘플 판매 중 288개 집계 행에는 할인액이 기록되어 있다.
- 레시피 원가는 재료별 사용량, 포장 구매량, 구매 가격 이력과 적용 판매채널로 계산할 수 있다. 재료 가격 이력의 최신 적용일은 2026-09-01이다.
- 비용 기록의 기준 필드는 날짜·분류·금액·인식 구분이다. 월별 비용 계획과 날짜별 비용은 같은 비용이므로 실제 손익에 함께 더하지 않는다.
- 재료 기준 단위는 g·ml·개다. 실사 수량은 24건뿐이고 재료 11종 중 2종에만 기록되어 있다.
- 영업달력은 2026-09-30까지 있으나 2026-09-19 이후는 기록 완료가 아니다. 연간 자료는 전체 1년이 아닐 수 있다.

### 시안에서 확인한 요소와 PRD 차이

- 화면은 대시보드, 판매 관리, 비용 관리, 재고 실사, 메뉴 수익성 분석으로 나뉜다. 판매·비용·실사 입력 창과 행별 수정·삭제 버튼이 있다.
- 판매 입력창은 날짜·메뉴·채널·수량을 보여준다. 자료에 있는 할인액과 결제 수수료 입력칸은 없다. 정확한 신규 판매 및 월 손익 계산을 위해 두 필드를 포함하는 것을 이 FRD에서 제안한다.
- 비용 입력창에는 날짜·분류·항목명·거래처·금액·결제 증빙·메모가 보인다. 자료와 PRD로 확인되는 공통 필드는 날짜·분류·금액이다. 나머지 항목과 비용 분류값은 시안 제안이며, 자료 기준으로 확정된 항목으로 보지 않는다.
- 재고 실사 입력창에는 실사 시각·재료·수량·단위가 보인다. 시안의 kg·팩 입력을 자료 기준 단위로 바꾸는 규칙은 PRD에서 정하지 않았다.
- 시안의 당일 마감, 월 계획 대 실제 비교, 안전재고 설정, 레시피(BOM) 편집, 원두 발주, CSV·엑셀 내보내기는 PRD에 없는 기능이므로 MVP에 포함하지 않는다. BOM은 메뉴 한 개에 들어가는 재료 배합표다.
- 시안은 가상 화면이다. 표시된 메뉴명, 거래처, ID, 수치가 원본 샘플과 다르며 버튼 일부는 안내 문구만 표시한다. 실제 계산·저장 동작의 근거로 쓰지 않는다.

## 기능 요구사항

### F-01. 샘플 자료와 마감 월 선택 — MVP

**사용자가 하는 일**  
대시보드에서 분석할 월을 선택한다.

**입력**  
선택한 연도·월. 시작 자료는 제공 샘플을 사용한다. 같은 기록인 엑셀과 JSON을 동시에 적재하지 않는다.

**프로그램이 하는 일**  
영업달력에서 선택 월의 모든 날짜가 기록 완료인지 확인한다. 모두 완료된 월만 확정 결과의 선택지로 제공한다. 월 일부만 완료되었거나 달력 정보가 없는 월은 확정 결과로 계산하지 않는다. 이 기준은 사용자가 선택한 “마감된 달만 표시”를 따른다. 시안의 당일 마감 버튼은 사용하지 않는다.

**화면과 파일에 나오는 결과**  
화면에 선택한 마감 월과 결과 기준 기간을 표시한다. 미마감 월은 확정 실적 목록에서 제외한다. MVP는 별도 보고서 파일을 만들지 않는다.

**오류나 예외가 있을 때의 동작**  
달력의 날짜가 빠졌거나 완료 여부가 비어 있으면 그 월의 마감 상태를 확인할 수 없다고 표시하고 확정 손익을 제공하지 않는다. 2026년 9월은 19일 이후가 미완료이므로 마감 월 목록에서 제외한다.

**직접 확인할 방법**  
2026년 8월은 선택 가능하고, 2026년 9월은 전체 날짜가 완료되기 전까지 확정 월로 선택되지 않는지 확인한다. 엑셀과 JSON을 중복 적재하지 않았는지 행 수와 ID를 대조한다.

### F-02. 판매 기록 입력·수정·삭제 — MVP

**사용자가 하는 일**  
판매 집계 행을 등록하고, 목록의 행별 수정·삭제 기능으로 기존 집계를 바로잡는다. 한 행은 특정 날짜·메뉴·채널의 합계이며 주문 한 건을 뜻하지 않는다.

**입력**  
날짜, 메뉴, 판매채널, 판매수량을 입력한다. 원본 자료에 있는 할인액과 결제 수수료는 신규 기록에서도 보존할 수 있도록 입력 필드로 제공하는 것을 제안한다. 판매 단가는 신규 기록 시 메뉴 자료의 등록 단가를 사용하고, 과거 기록은 각 행에 저장된 당시 단가를 유지한다. 할인은 집계 행 전체 금액으로 입력한다.

- 원본 판매 필드: 날짜, 메뉴 ID, 채널, 수량, 판매 당시 단가, 할인 금액, 순매출, 결제 수수료, 레시피 버전, 당시 재료·포장 원가
- 시안과 다른 점: 할인액과 결제 수수료 입력칸이 빠져 있다. 신규 판매에서 수수료율을 임의로 추정하지 않도록 실제 수수료 금액을 입력하는 방식을 제안한다.

**프로그램이 하는 일**  
신규 기록의 순매출은 판매 단가와 수량에서 집계 할인액을 반영해 계산한다. 기존 판매 행은 자료에 저장된 순매출을 보존한다. 판매 기록 변경·삭제 후 메뉴 수익성과 월 손익에 반영한다. 같은 날짜·메뉴·채널의 집계 행이 이미 있으면 별도 중복 행을 만들지 않고 기존 행을 수정하도록 안내하는 것을 제안한다.

**화면과 파일에 나오는 결과**  
판매 관리 화면의 목록에 날짜·메뉴·채널·수량·금액이 보인다. 검색·날짜·메뉴·채널 필터는 시안에 있으나, 조회 조건은 이번 MVP의 확정 범위가 아니다. 판매 엑셀 내보내기 버튼은 MVP에 포함하지 않는다. 저장 파일은 생성하지 않고 앱 기록에 보존한다.

**오류나 예외가 있을 때의 동작**  
날짜·메뉴·채널·수량 등 필수 값 누락, 유효하지 않은 메뉴·채널, 0보다 작은 수량, 음수 할인·수수료, 할인액이 판매 총액보다 큰 경우 저장하지 않고 해당 항목을 알린다. 숫자 입력이 빈칸이면 0으로 취급하지 않는다. 수수료가 미입력인 행은 수수료 0원으로 보지 않는다. 자료에 없는 날짜는 마감 여부를 확인할 수 없다고 알리고 확정 월 분석에서 제외한다. 삭제는 대상을 확인한 후 처리하는 것을 제안한다.

**직접 확인할 방법**  
샘플의 아메리카노 단가를 사용해 10잔, 총 할인 ₩1,000을 입력하면 순매출이 ₩39,000인지 확인한다(예시 단가 ₩4,000). 할인액 또는 수수료를 비워 저장했을 때 0원으로 조용히 바뀌지 않는지 확인한다. 수정·삭제 뒤 관련 월 결과가 함께 바뀌는지 확인한다.

### F-03. 비용 기록 입력·수정·삭제 — MVP

**사용자가 하는 일**  
날짜별 실제 비용을 추가하거나 기존 항목을 수정·삭제한다.

**입력**  
원본 자료로 확인되는 날짜, 비용 분류, 금액을 입력한다. 기존 데이터의 인식 구분은 가져온 값을 보존한다. 거래처·품목명·결제 증빙·메모는 시안에 있으나 자료 필드와 다르므로 MVP 필수 입력값으로 확정하지 않는다.

**프로그램이 하는 일**  
날짜별 실제 비용을 해당 월에 귀속한다. 월별 비용 계획은 실제 지출로 더하지 않는다. 제공 자료의 기존 비용 분류를 기본 선택값으로 삼으며, 시안에만 있는 “원재료비” 분류를 추가하면 메뉴 재료 원가와 중복될 수 있으므로 별도 확인 전 사용하지 않는다.

**화면과 파일에 나오는 결과**  
비용 관리 화면에 날짜·분류·금액을 목록으로 표시하고, 선택한 마감 월 손익에 해당 월의 비용을 반영한다. 비용 내역 파일 내보내기는 MVP에 포함하지 않는다.

**오류나 예외가 있을 때의 동작**  
날짜·분류·금액이 없거나 금액이 숫자가 아니면 저장하지 않는다. 빈 금액을 0으로 처리하지 않는다. 월별 비용 계획만 있고 날짜별 비용 기록이 없으면 계획 금액을 실제 손익에 대신 넣지 않고 실제 비용 자료가 부족하다고 표시한다.

**직접 확인할 방법**  
날짜와 금액이 있는 새 비용을 입력해 해당 월 비용 및 손익에 한 번만 반영되는지 확인한다. 월별 계획 자료를 별도로 더해도 실제 손익이 변하지 않는지 확인한다. 원본 8개 비용 분류와 시안의 분류가 서로 다름을 목록에서 확인한다.

### F-04. 실제 재고 실사 기록과 마지막 수량 확인 — MVP

**사용자가 하는 일**  
재료를 선택하고 실제로 센 수량과 실사 날짜·시각을 기록한다. 재료별 마지막 실사값을 확인한다.

**입력**  
재료, 실사 날짜·시각, 실제 수량, 단위를 입력한다. PRD의 기준 단위는 g·ml·개다. 시안은 kg·팩도 허용하지만 단위 변환 규칙이 미정이다. FRD 제안은 kg를 g으로 환산하고 팩 입력은 해당 재료의 구매 포장량으로 환산하는 것이다. 예: 2kg 원두는 2,000g, 1팩이 1,000ml인 우유는 1팩을 1,000ml로 기록한다. 변환할 포장량이 없는 경우 저장하지 않는다.

**프로그램이 하는 일**  
실사 이력을 날짜·시각과 함께 저장하고, 재료별 가장 최근 실사값과 날짜를 표시한다. 실사 기록이 없으면 수량 0이 아니라 “실사 기록 없음”을 표시한다. MVP는 입고·폐기 기록이나 판매량에서 현재 재고를 추정하지 않는다.

**화면과 파일에 나오는 결과**  
재료 11종 목록에 마지막 실사 수량·단위·날짜 또는 “실사 기록 없음”을 표시한다. 실사 서식 파일 내려받기 및 엑셀 저장은 시안에만 있으며 MVP에서 제공하지 않는다.

**오류나 예외가 있을 때의 동작**  
재료·시각·수량이 누락되거나 알 수 없는 단위, 음수 수량, 숫자가 아닌 값이면 저장하지 않는다. 0은 실제로 센 재고가 없는 값으로 저장할 수 있고, 기록 없음과 구분한다. 오래된 실사는 현재 시점의 실제 수량으로 단정하지 않고 실사일과 함께 보여준다.

**직접 확인할 방법**  
실사 기록이 없는 재료 한 종을 입력하면 날짜와 수량이 목록에 나타나는지 확인한다. 수량 0 입력은 “0”으로, 입력하지 않은 재료는 “실사 기록 없음”으로 표시되는지 확인한다. 단위 변환은 위 예시로 확인한다.

### F-05. 마감 월의 메뉴별 수익성 확인 — MVP

**사용자가 하는 일**  
마감 월을 선택하고 메뉴별 판매량·원가·공헌이익을 확인한다. 공헌이익은 메뉴 판매에서 해당 메뉴의 직접 원가를 뺀 금액이다.

**입력**  
선택한 마감 월의 판매 기록, 메뉴별 레시피, 판매채널, 재료 구매 포장량과 최신 가격 자료를 사용한다. 수익성 기준은 사용자가 확인한 대로 과거 판매도 최신 레시피와 현재 가격으로 다시 계산한다. 샘플의 최신 가격 기준일은 2026-09-01이다.

**프로그램이 하는 일**  
제안 계산 기준:

1. 재료 1단위 가격 = 구매 포장 가격 ÷ 포장 안의 기준 단위 수량
2. 메뉴 1개 원가 = 해당 채널에 적용되는 레시피 재료 사용량에 재료 1단위 가격을 반영한 항목별 원가 합계
3. 메뉴 공헌이익 = 할인 반영 순매출 합계 − (판매수량 × 최신 레시피 기준 메뉴 1개 원가)
4. 메뉴 공헌이익에는 결제 수수료를 빼지 않는다. 수수료는 월 손익에 별도로 반영한다. 이는 사용자가 선택한 기준이다.

작은 예: 샘플의 메뉴 M01은 원두 20g을 사용하고, 원두 1,000g의 2026-09-01 적용 가격은 ₩24,840이다. 원두 원가만 계산하면 20g은 ₩496.8이다. 10잔을 각 ₩4,000에 판매하고 총 할인액이 ₩1,000이면 순매출은 ₩39,000이다. 포장 재료가 없는 판매채널이라고 가정하면 현재 원가 합계는 ₩4,968, 수수료 전 메뉴 공헌이익은 ₩34,032다. 다른 레시피 재료가 적용되는 채널은 해당 재료 원가도 더한다.

공헌이익률을 표시할 때는 공헌이익 ÷ 순매출을 쓰는 것을 제안한다. 위 예에서는 약 87.3%다. 시안에는 비율이 있지만 분모 기준은 PRD에 없으므로 이 비율 기준은 확인이 필요하다.

**화면과 파일에 나오는 결과**  
메뉴별 판매량, 등록 판매단가, 최신 레시피 원가, 공헌이익, 제안 공헌이익률을 표시한다. PRD는 메뉴별 수익성 확인을 요구하므로 시안의 상위 5개만이 아니라 전체 메뉴를 확인할 수 있어야 한다. 분석 파일 다운로드는 MVP에서 제공하지 않는다.

**오류나 예외가 있을 때의 동작**  
메뉴에 적용할 최신 레시피나 재료 가격이 없으면 원가를 0으로 계산하지 않는다. 해당 메뉴를 “계산 불가/자료 확인 필요”로 표시하고, 불완전한 결과를 정상 합계처럼 표시하지 않는다. 순매출이 0이면 공헌이익률 대신 계산할 수 없음을 표시한다. 최신 가격이 자료의 기준일(2026-09-01)보다 오래되면 기준일을 함께 알려준다.

**직접 확인할 방법**  
위 M01 예시의 원가 ₩496.8/잔과 공헌이익 ₩34,032를 독립 계산값과 비교한다. 동일한 판매량에서 원가 자료를 바꾸면 과거 판매의 재산정 결과가 바뀌는지 확인한다. 결제 수수료는 메뉴 공헌이익에 포함되지 않고 월 손익에서 한 번만 차감되는지 확인한다.

### F-06. 마감 월의 재산정 손익 확인 — MVP

**사용자가 하는 일**  
마감 월을 선택해 해당 월의 손익 결과를 확인한다.

**입력**  
해당 월의 순매출, 최신 레시피·가격 기준 재료 및 포장 원가, 기록된 결제 수수료, 날짜별 실제 비용을 사용한다. 월별 비용 계획은 입력 근거로 사용하지 않는다.

**프로그램이 하는 일**  
제안 계산 기준:

재산정 월 손익 = 순매출 합계 − 최신 레시피·가격 기준 판매원가 − 기록된 결제 수수료 − 날짜별 실제 비용 합계

이는 과거 실제 지출 원가를 보존한 회계 손익이 아니다. 메뉴 원가가 최신 가격으로 소급 재산정되므로 화면에는 “현재 원가 기준 재산정 손익”이라고 표시한다.

작은 예: 순매출 ₩39,000, 현재 메뉴 재료원가 ₩4,968, 결제 수수료 ₩600, 날짜별 비용 ₩5,000이면 재산정 손익은 ₩28,432다. 월별 비용 계획 ₩20,000은 이 결과에 더하지 않는다.

**화면과 파일에 나오는 결과**  
선택 월의 순매출, 재산정 원가, 결제 수수료, 실제 날짜별 비용, 재산정 손익을 화면에 구분해 표시한다. MVP는 손익 파일을 별도로 출력하지 않는다.

**오류나 예외가 있을 때의 동작**  
필수 값이 빈칸이거나, 해당 월의 마감 여부·가격·레시피를 확인할 수 없으면 빈칸을 0으로 간주하지 않는다. 누락 항목을 표시하고 확정된 손익처럼 보이지 않게 한다. 월 비용 계획만 있는 경우 실제 비용으로 대체하지 않는다.

**직접 확인할 방법**  
위 작은 예의 합계가 ₩28,432인지 확인한다. 월별 비용 계획을 바꾸어도 월 손익이 변하지 않는지, 날짜별 비용을 수정하면 한 번만 반영되는지 확인한다. 원가 기준일과 “재산정” 표시가 결과에 보이는지 확인한다.

### F-07. 저장·오류 처리·결과 검증 — MVP 공통

**사용자가 하는 일**  
판매·비용·실사 입력을 저장하고, 목록에서 수정하거나 삭제한다.

**입력**  
각 기능에 정한 날짜·식별 대상·수량·금액 등의 값.

**프로그램이 하는 일**  
저장된 기록을 화면과 계산 결과에 반영하고, 다시 열어도 보존한다. 입력값이 잘못되면 문제 항목을 안내하고 저장하지 않는다. 저장 실패 시 성공 안내를 표시하지 않고 입력 내용을 유지하는 것을 제안한다. 기록을 수정·삭제하면 연관된 월별 결과를 갱신한다.

**화면과 파일에 나오는 결과**  
성공 시 변경된 목록과 분석 결과를 표시한다. MVP에는 엑셀·CSV 내보내기나 백업 파일이 없다. 백업·복원은 F-12에서 다룬다.

**오류나 예외가 있을 때의 동작**  
저장에 실패하면 사용자 입력을 유지하고 실패 사실을 알린다. 필수값 오류, 수량·금액 형식 오류, 잘못된 참조를 성공한 것처럼 처리하지 않는다. 삭제 확인을 취소하면 원본은 유지한다.

**직접 확인할 방법**  
입력한 기록을 저장한 뒤 앱을 다시 열어 확인한다. 수정·삭제 후 목록과 월별 결과가 함께 변하는지 확인한다. 빈칸·0·잘못된 숫자를 각각 입력해 구분되는지 확인한다.

### F-08. 엑셀 양식 내려받기와 자료 가져오기 — 수업 후

**사용자가 하는 일**  
제공된 양식에 판매·비용 기록을 채워 가져온다.

**입력**  
내려받은 양식과 채워 넣은 판매·비용 행. 엑셀과 JSON이 같은 샘플 데이터라는 안내를 표시한다.

**프로그램이 하는 일**  
제안: 가져오기 전에 열 제목, 날짜, 단위, 필수값, ID와 중복 후보를 검사하고 가져올 수 없는 행을 미리 보여준다. 중복 행을 덮어쓸지 건너뛸지, 전체 취소할지 부분 가져오기를 허용할지는 아직 정하지 않았다.

**화면과 파일에 나오는 결과**  
수업 후 기능으로 판매·비용 엑셀 양식을 내려받고, 가져온 결과와 오류 행 안내를 표시한다. 기존 원장 전체를 CSV로 내보내는 기능은 PRD에 명시되지 않아 포함하지 않는다.

**오류나 예외가 있을 때의 동작**  
잘못된 형식, 열 제목 누락, 날짜·숫자·단위 오류, 알 수 없는 메뉴·재료 ID를 알아보기 쉽게 표시한다. 가져오기 중 일부 행만 저장할지 여부는 미정이므로 구현 전 정해야 한다. 실패한 행을 정상 저장한 것처럼 보고하지 않는다.

**직접 확인할 방법**  
정상 양식과 열 제목이 틀린 양식을 각각 가져와 성공·오류 행이 구분되는지 확인한다. 같은 자료를 엑셀과 JSON 양쪽에서 가져올 때 중복 방지 기준을 확인한다.

### F-09. 일·주·월·분기·반기·연간 조회 — 수업 후

**사용자가 하는 일**  
원하는 기간 단위를 선택해 판매·손익 결과를 조회한다.

**입력**  
조회 단위와 기간.

**프로그램이 하는 일**  
MVP의 마감 월 기준을 다른 기간에도 적용하는 것을 제안한다. 주 시작 요일, 분기·반기의 시작월, 회계연도, 기간 일부만 있는 연간 결과의 표시 방법은 미정이다.

**화면과 파일에 나오는 결과**  
선택 기간의 메뉴 수익성·손익·재고 관련 결과를 표시한다. 기간 결과 파일은 PRD에 포함되지 않았다.

**오류나 예외가 있을 때의 동작**  
기간 경계를 정할 수 없거나 일부 기간의 자료가 빠지면 전체 기간 결과인 것처럼 표시하지 않는다. 부분 연도는 부분 기간임을 명시한다.

**직접 확인할 방법**  
주·월 경계에 걸친 판매와 부분 연도를 포함하는 시험 자료를 준비해 어느 기간에 집계되는지 합의된 기준과 대조한다.

### F-10. 재료 입고·폐기 기록과 발주량 참고 — 수업 후

**사용자가 하는 일**  
재료 입고 또는 폐기 일자, 재료, 수량을 기록하고 부족 가능성과 참고 발주량을 확인한다.

**입력**  
자료에는 입고·폐기·실사조정, 공급사, 기준 단위, 구매 포장량, 납기일, 안전재고일 정보가 있다. 실제 사용자가 입력할 필드와 음수·양수 부호 규칙은 추후 확정한다.

**프로그램이 하는 일**  
정확한 발주 기준은 PRD에서 미정이다. 계산 제안은 최근 영업일 평균 사용량으로 납기일과 안전재고 기간의 예상 사용량을 구해, 실사·입고·폐기 기록과 비교하고 구매 포장 단위로 올림하는 방식이다.

예시 제안: 하루 평균 100g 사용, 납기 2영업일, 안전재고 2영업일이면 필요한 기준량은 400g이다. 확인된 사용 가능량이 300g이고 구매 포장이 1,000g이면 부족 참고량 100g을 표시하고 발주 참고는 1포장으로 올림한다. 수요 기간·평균 사용량·올림 규칙은 확정되지 않았다.

**화면과 파일에 나오는 결과**  
수업 후 재료 변동 목록과 부족·발주 참고량을 표시할 수 있다. 공급사 발주서나 발주 파일 생성은 PRD에 없어 포함하지 않는다.

**오류나 예외가 있을 때의 동작**  
재료 단위·포장량·납기·안전재고·실사 수량 자료가 없으면 임의의 발주량을 만들지 않는다. 실제 실사 수량이 오래됐으면 마지막 실사일을 표시하고 신뢰에 주의가 필요함을 알린다.

**직접 확인할 방법**  
위 작은 예로 발주 참고량과 구매 포장 올림 결과를 검산한다. 입고·폐기 한 건씩 추가하고 변동 내역과 잔량이 기준 기록에 맞는지 대조한다.

### F-11. 예상 손익 — 수업 후

**사용자가 하는 일**  
예상 기간의 손익을 조회한다.

**입력**  
예상 기간과 기준값이 필요하나, PRD에서는 전망 방법·가정·기간을 정하지 않았다.

**프로그램이 하는 일**  
예상 손익 계산 방법이 승인되기 전에는 실적과 섞거나 실제 결과처럼 표시하지 않는다. 과거 평균, 비용 계획, 사용자가 직접 입력한 예상값 중 어느 것을 사용할지 미정이다.

**화면과 파일에 나오는 결과**  
방법이 확정된 뒤 예상 매출·비용·손익과 기준 기간을 구분해 표시한다. MVP에서는 제공하지 않는다.

**오류나 예외가 있을 때의 동작**  
필수 전망 기준이 없거나 자료가 부족하면 예상값 대신 부족한 기준을 표시한다.

**직접 확인할 방법**  
전망 기준이 합의된 뒤 작은 입력 사례의 예상 매출·비용·손익을 손계산 결과와 비교한다. 현재는 계산식 확정 전이므로 완료 판정 대상이 아니다.

### F-12. 데이터 백업·복원 — 수업 후

**사용자가 하는 일**  
데이터 백업 파일을 내려받고 필요할 때 백업 파일을 선택해 복원한다.

**입력**  
백업 대상과 복원할 파일. 파일 형식, 전체 교체/병합 방식은 미정이다.

**프로그램이 하는 일**  
제안: 복원 전 파일 구조와 데이터 유효성을 검사하고 복원 결과를 안내한다. 잘못된 파일이면 기존 데이터를 바꾸지 않는다. 복원 시 전체 교체와 병합 중 무엇을 적용할지는 사전 합의가 필요하다.

**화면과 파일에 나오는 결과**  
백업 시 파일을 제공하고, 복원 시 성공·실패를 화면에 알린다. 구체적인 형식·파일명·저장 위치는 정하지 않았다.

**오류나 예외가 있을 때의 동작**  
파일을 읽을 수 없거나 형식이 맞지 않으면 복원하지 않고 기존 자료를 유지한다. 일부 자료만 복원할지 여부는 미정이다.

**직접 확인할 방법**  
백업 후 복원한 데이터의 행 수와 대표 합계를 비교한다. 손상된 파일로 복원할 때 기존 자료가 바뀌지 않는지 확인한다.

## 시안과 PRD의 미정 항목 및 제안

아래 제안은 FRD에 계산·오류 처리 방법을 적기 위해 정리했으며, PRD에서 사용자가 확정한 내용과 구별한다.

1. 판매 입력창에는 원본 판매 데이터와 같이 할인 총액과 결제 수수료를 추가한다. 순매출은 판매 단가×수량−할인 총액으로 제안한다. 시안에는 두 입력칸이 없다.
2. 신규 판매 단가는 메뉴 자료의 등록 단가를 사용하고, 과거 판매의 매출·할인은 기록 당시 값을 보존한다. 메뉴 판매가를 언제 갱신할지 기능은 MVP에 없다.
3. 메뉴별 공헌이익률은 공헌이익÷순매출로 제안했다. 시안은 비율을 표시하지만 계산 기준을 설명하지 않는다.
4. 실사 단위를 kg·팩으로 허용하려면 기준 단위로 환산해야 한다. 팩 입력은 재료별 포장량을 이용하는 방식을 제안했으며 확인이 필요하다.
5. 판매 관리 시안은 배달 채널도 보여주지만 샘플 데이터에서 확인한 채널과 다를 수 있다. MVP 선택지는 제공 샘플에 있는 값만 사용한다.
6. 비용 관리 시안의 원재료비·거래처·결제 증빙·메모는 원본 비용 자료와 차이가 있다. 기존 비용 분류와 날짜·금액을 우선하고, 추가 필드·분류는 확인이 필요하다.
7. 엑셀 가져오기 중복 처리, 주 시작 요일, 회계 기간, 발주량 기준, 예상 손익 가정, 백업 복원 방식, 사용자 권한과 자료 공유는 미정이다.
8. 시안에 있는 일일 마감·예산 비교·안전재고 편집·레시피 편집·내보내기·발주서 생성은 현재 PRD에 없는 기능이다. 사용자가 추가를 승인하기 전에는 요구사항에 넣지 않는다.

## 완료 기준

- MVP 사용자가 샘플 자료에서 시작해 판매·비용 입력/수정/삭제, 실사 수량 입력, 마감 월의 메뉴 수익성·재산정 손익 확인을 수행할 수 있다.
- 저장된 값이 앱을 다시 열어도 남으며, 수정·삭제가 목록 및 연관 결과에 반영된다.
- 기록 완료가 아닌 달은 확정 결과에서 제외되고, 월별 비용 계획은 실제 비용과 중복되지 않는다.
- 현재 레시피·재료 가격 재산정, 할인, 결제 수수료, 실제 날짜별 비용의 역할이 분리되어 작은 예시를 손계산한 값과 일치한다.
- 단위·기간·빈칸·0의 구분, 누락된 원가 자료, 실사 기록 없음이 잘못된 0 또는 정상 결과로 둔갑하지 않는다.
- 잘못된 입력은 이유를 안내하고, 저장 실패·취소·삭제 후 데이터 상태가 확인 가능하다.
- 대표 기능에서 정상 입력과 잘못된 입력을 각각 확인하고, 배포된 프로그램에서 전체 핵심 흐름을 완료할 수 있다.
