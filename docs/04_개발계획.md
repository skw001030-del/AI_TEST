- 실행 앱과 테스트 결과는 `README.md`, `docs/05_테스트결과.md`에 기록한다.

## 전체 작업 순서와 나눈 이유

자료 접근을 먼저 보호하고 샘플·마감 월을 준비한 뒤, 입력 기록을 저장한다. 저장된 판매와 현재 레시피·가격으로 메뉴 수익성을 계산하고, 이어 월 손익과 마지막 실사 수량을 연결한다. 판매·재고를 저장하기 전에 분석 화면을 만들면 샘플 확인과 오류 찾기가 어려우므로 이 순서를 사용한다.

| 순서 | 작업 | 예상 시간 |
|---|---|---:|
| 1 | 범위·완료 기준 확인 | 20분 |
| 2 | 기존 시안을 MVP 화면 흐름에 맞춰 정리 | 30분 |
| 3 | Epic 구현 및 각 Epic 화면 확인 | 100분 |
| 4 | 전체 회귀 확인: 앞의 기능이 뒤 작업 후에도 맞는지 재확인 | 50분 |
| 5 | Vercel 데모 배포와 배포본 핵심 흐름 확인 | 40분 |
| **합계** | **4시간** | **240분** |

시간은 추정치다. Epic 구현과 사용자 화면 확인은 아래 Story 시간의 합계인 100분이다. 이 일정은 개발 계정과 가상 샘플 파일을 사용할 수 있다는 전제다. 외부 서비스 계정 생성이나 배포 설정에 문제가 생기면 일정이 늘 수 있다.

### 확인된 구현 범위 조정

- **비용 CRUD는 수업 후로 미룬다.** 수업 중에는 샘플 비용을 읽기 전용으로 보여주고 월 손익에 반영한다. 실습 중 새 비용을 추가·수정·삭제할 수는 없다. 이 조정으로 입력→메뉴 수익성→월 손익과 재고 확인 흐름을 100분에 우선 완성한다.
- **실사 입력은 기본 단위 g/ml/개만 받는다.** kg·팩은 자동 환산하지 않는다. 예: 2kg 원두는 사용자가 2,000g으로 환산해 입력한다. 단위 자동 환산은 수업 후로 둔다.
- 계산 정확성, 영구 저장, 기본 오류 처리와 검증은 축소하지 않는다. 마감 월, 현재 레시피·가격 재산정, 수수료와 실제 비용의 구분, 빈칸과 0의 차이를 유지한다.
- 현재 미리보기는 별도 서비스 계정 없이 실행할 수 있도록 Node.js 로컬 서버와 SQLite를 사용한다. TRD의 Next.js·Supabase·Vercel 배포 구성은 연결할 사용자 소유 서비스 정보가 준비되지 않아 적용하지 않았으며, 이 차이를 배포 전 결정 사항으로 기록한다.

## Epic·Story 개요

**Epic 3개, Story 8개**다. Epic은 의존성이 있는 작업 묶음이고, Story는 사용자가 달성하는 기능 단위다. 각 Epic의 시간은 구현과 즉시 화면 확인을 합친 예상치다.

## EPIC 1. 로그인하고 판매 기록을 시작한다 — 40분

### Story 1. 운영자로 로그인한다 — 8분

**사용자 관점:** 운영자 계정으로 로그인해 매장 자료를 안전하게 연다.

- **사용자가 할 수 있는 일:** 운영자 1인 계정으로 로그인·로그아웃한다.
- **자동 검사:** 비로그인 요청은 거부되고, 잘못된 로그인 정보로는 자료를 볼 수 없으며, 정상 계정에만 세션이 발급되는지 확인한다.
- **화면에서 확인:** 로그아웃 상태에서 결과 페이지에 접근하면 로그인 화면으로 이동한다. 정상 로그인 후에는 샘플 자료 화면이 열린다.

### Story 2. 샘플 자료에서 마감 월을 선택한다 — 10분

**사용자 관점:** 제공된 샘플을 시작 자료로 열고 확정 결과가 있는 월을 고른다.

- **사용자가 할 수 있는 일:** 샘플 데이터와 조회할 월을 확인한다.
- **자동 검사:** 초기 자료 적재에 JSON만 사용했는지, 판매 ID와 날짜·메뉴·채널 조합이 중복되지 않았는지 확인한다. 기준 건수는 판매 6,112건, 날짜별 비용 3,560건, 재료 11종, 메뉴 8종, 레시피 22건, 가격 이력 33건, 영업달력 457일이다.
- **화면에서 확인:** 2026년 8월은 마감 월로 선택되고, 2026년 9월은 미완료 날짜가 남아 있어 확정 결과에서 제외된다.

### Story 3. 판매 집계 기록을 입력·수정·삭제한다 — 22분

**사용자 관점:** 날짜·메뉴·채널별 집계 판매 기록을 관리해 월별 결과를 정확히 만든다.

- **사용자가 할 수 있는 일:** 날짜, 메뉴, 판매채널, 수량, 총 할인액, 실제 결제 수수료를 입력하거나 기존 판매 집계를 수정·삭제한다. 행은 주문 한 건이 아니라 날짜·메뉴·채널별 합계다.
- **자동 검사:** 필수값·메뉴·채널을 확인하고 수량은 양수, 할인·수수료는 음수가 아니어야 한다. 할인액은 총 판매액보다 클 수 없다. 빈칸은 0으로 취급하지 않으며, 기존 날짜·메뉴·채널 조합은 중복으로 더하지 않는다. 저장·수정·삭제가 DB에 반영되고 다시 조회되는지 검사한다.
- **화면에서 확인:** M01 10잔, 잔당 ₩4,000, 총 할인 ₩1,000을 입력하면 순매출이 **₩39,000**이다. 저장 후 새로고침해도 기록이 남고, 수정·삭제한 값은 목록과 관련 결과에 반영된다.

**EPIC 1 완료 기준:** 실제 로그인과 DB에서 불러온 샘플이 보이고, 운영자가 판매 집계를 입력·수정·삭제한 결과가 다시 열어도 남는다. 화면에는 저장된 실제 값이 표시된다.

## EPIC 2. 실사 재고와 메뉴 수익성을 확인한다 — 37분

### Story 4. 실제 재고 실사를 기록한다 — 12분

**사용자 관점:** 직접 센 재료 수량과 실사 시각을 기록한다.

- **사용자가 할 수 있는 일:** 재료, 실사일·시각, 실제 수량을 기본 단위 g/ml/개로 입력한다. kg·팩을 쓴 사용자는 입력 전에 직접 환산한다.
- **자동 검사:** 재료·날짜·수량 누락, 숫자가 아닌 값, 음수, 기본 단위 외 입력을 저장 전에 거부한다. 수량 0은 허용하되 빈칸과 다르게 저장한다.
- **화면에서 확인:** 2kg 원두를 2,000g으로 환산해 입력하면 2,000g과 실사일이 나타난다. 새로고침 후에도 같은 값이 보인다.

### Story 5. 마지막 실사 수량과 미실사 재료를 확인한다 — 7분

**사용자 관점:** 재료별로 마지막으로 직접 확인한 수량과 날짜를 본다.

- **사용자가 할 수 있는 일:** 재료 11종의 마지막 실사값 또는 실사 기록이 없는 상태를 확인한다.
- **자동 검사:** 재료마다 가장 최근 실사 시각의 기록을 선택하고, 기록이 없는 재료를 0으로 변환하지 않는지 확인한다.
- **화면에서 확인:** 새 실사값을 입력한 재료에는 새 수량·날짜가 보인다. 기록이 없는 재료에는 “실사 기록 없음”이 표시된다. 기존 샘플에는 11종 중 2종만 실사 기록이 있을 수 있음을 확인한다.

### Story 6. 마감 월의 메뉴별 수익성을 확인한다 — 18분

**사용자 관점:** 전체 메뉴별 판매량·현재 가격 기준 원가·공헌이익을 비교한다. 공헌이익은 메뉴 판매에서 직접 원가를 뺀 금액이다.

- **사용자가 할 수 있는 일:** 마감 월을 골라 메뉴별 수익성 표를 확인한다.
- **자동 검사:** 과거 판매도 최신 레시피와 재료 가격으로 재산정하고 판매채널별 레시피를 반영하는지 검사한다. 결제 수수료는 메뉴 공헌이익에서 빼지 않는다. 원가 자료가 없으면 0으로 대체하지 않는다.
- **화면에서 확인:** FRD 예시에서 원두 1,000g 가격이 ₩24,840이고 M01 한 잔에 20g이 쓰이면 원가는 **₩496.8/잔**이다. 10잔 원가는 **₩4,968**이며, 할인 후 순매출 ₩39,000에서 수수료 전 공헌이익은 **₩34,032**다. 기준 가격일은 2026-09-01로 표시한다.

**EPIC 2 완료 기준:** 실제 실사 기록과 마지막 수량 상태가 화면에 보이고, 같은 월의 전체 메뉴 수익성이 최신 레시피·가격으로 계산되어 화면에서 확인된다.

## EPIC 3. 마감 월 손익과 전체 흐름을 검증한다 — 23분

### Story 7. 마감 월의 재산정 손익을 확인한다 — 15분

**사용자 관점:** 월별 결과에서 실제 날짜별 비용과 현재 원가 기준 손익을 구분해 본다.

- **사용자가 할 수 있는 일:** 선택한 마감 월의 순매출, 재산정 원가, 결제 수수료, 날짜별 실제 비용과 손익을 확인한다. 비용 상세는 샘플 자료를 조회만 할 수 있다.
- **자동 검사:** 월 손익에 최신 레시피·가격 기준 원가와 실제 결제 수수료·날짜별 비용만 반영되는지 검사한다. 월 비용 계획을 추가하지 않고, 미마감 월은 확정 결과에서 제외한다.
- **화면에서 확인:** FRD 소예시에서 ₩39,000 − ₩4,968 − ₩600 − ₩5,000은 **₩28,432**다. 화면은 이를 “현재 원가 기준 재산정 손익”으로 표시하고 월 계획액은 포함하지 않는다.

### Story 8. 저장한 판매가 모든 결과에 반영되는지 확인한다 — 8분

**사용자 관점:** 판매 기록 하나를 저장하고, 메뉴 수익성 및 월 손익에서 같은 변경을 확인해 기록과 분석이 일치하는지 안다.

- **사용자가 할 수 있는 일:** 미리 준비된 테스트용 판매 조합을 입력하고 핵심 흐름을 처음부터 끝까지 확인한다.
- **자동 검사:** 유효값은 저장 후 다시 읽은 값과 같고, 입력 오류·가격 누락·저장 실패가 성공 처리되지 않는지 확인한다. 같은 판매 변경이 메뉴 수익성과 손익에 각각 한 번 반영되고 수수료는 월 손익에서 한 번만 차감되는지 확인한다.
- **화면에서 확인:** 테스트 판매를 저장하고 새로고침한 뒤, 판매 목록·메뉴 공헌이익·월 손익의 값이 갱신되어 있다. 실사 수량과 “실사 기록 없음” 표시도 유지된다.

**EPIC 3 완료 기준:** 배포 전 미리보기에서 판매 입력 → 메뉴 수익성 → 같은 마감 월 손익 → 재료별 마지막 실사값까지 완료한다. 각 결과가 저장 자료와 일치하고 잘못된 입력은 이유와 함께 거부된다.

## 수업 후 확장 기능

다음 기능은 이번 100분 범위와 완료 조건에 넣지 않는다.

- 비용 기록 입력·수정·삭제
- 엑셀 양식 내려받기와 판매·비용 가져오기
- 일·주·분기·반기·연간 조회
- 재료 입고·폐기 기록과 발주 참고량
- 예상 손익
- 백업·복원
- kg·팩 재고 수량 자동 환산

시안의 당일 마감, 레시피 편집, 안전재고 설정, 월 계획 대 실제 비교, 공급사 발주서와 CSV·엑셀 내보내기도 PRD에 없는 기능이므로 이번 계획에 포함하지 않는다.
